## 一、项目题

### 1. 自我介绍

**参考回答：**

我主要关注大模型应用和 Agent 工程，做过检索增强、工具调用、上下文管理和任务编排相关工作。项目中我负责过需求拆解、核心链路实现、异常处理和效果评测，比较关注的不只是模型能不能生成答案，还包括检索是否命中证据、工具是否安全可靠、任务能否恢复以及延迟和成本。下面我重点介绍一个和岗位最相关的项目，并说明我的具体职责和结果。

> 面试时补充学校/专业、真实项目、负责模块和可核验指标，控制在 60~90 秒。

### 2. 请详细介绍你的 AI 项目

**参考回答框架：**

按“业务背景 → 用户输入 → Agent 链路 → 我的职责 → 难点 → 结果”讲。链路可以描述为：请求接入后先做意图和风险判断，再由 Planner 生成结构化任务；Retriever 召回带来源的证据；Tool Gateway 负责鉴权、参数校验和执行；State Store 保存计划、工具结果和重试状态；最终由校验器验收后返回。

不要只报“用了某模型、某向量库”。需要说明为什么选它、失败时如何处理，以及你真正写过哪些代码。结果使用真实数据，如任务完成率、引用准确率、P95 延迟、人工耗时或成本变化；没有数据就明确说没有做过线上统计。

### 3. 项目中的面试评分，如何进行结构化输出？从哪几个维度评分？

**参考回答：**

先把评分标准定义成版本化 rubric，而不是让模型自由打分。输入包括面试题、候选人回答、岗位要求和评分规则；输出使用 JSON Schema，例如：

```json
{
  "total": 82,
  "dimensions": {
    "technical_depth": {"score": 28, "max": 35, "evidence": ["..."]},
    "problem_solving": {"score": 22, "max": 25, "evidence": ["..."]},
    "engineering": {"score": 18, "max": 20, "evidence": ["..."]},
    "communication": {"score": 14, "max": 20, "evidence": ["..."]}
  },
  "missing_evidence": ["..."],
  "final_comment": "..."
}
```

维度通常包括技术基础/深度、项目真实性与结果、问题分析和编码能力、工程质量（稳定性/安全/评测）、沟通表达与岗位匹配。每个分数必须绑定回答中的证据和扣分理由；模型输出后做 Schema、范围、权重和引用校验，低置信度进入人工复核。总分由程序按权重计算，避免模型算错。

### 4. 项目中的 RAG 知识用到了哪些？离线上传和在线问答如何进行？

**参考回答：**

离线链路是“采集 → 解析 → 清洗去重 → 按标题/段落/表格结构切片 → 补充文档、权限、版本和时间元数据 → Embedding → 写入向量索引，同时建立 BM25/关键词索引”。增量更新使用文档版本或内容哈希，删除要同步下线索引，切换索引时保留旧版本回滚能力。

在线链路是“问题改写/拆分 → 权限过滤 → 向量与关键词并行召回 → 合并去重 → Rerank → 按 token 预算组装上下文 → 模型生成 → 引用和事实校验”。无结果时应说明依据不足或追问，而不是编造。多租户系统要在召回前后都做权限过滤，并记录 query、候选、版本、延迟和最终引用，方便定位 badcase。

## 二、Agent 基础

### 5. 如何理解 Agent 中 Harness 的概念？

**参考回答：**

Harness 是包围模型的运行时控制层，把一次模型调用变成可控任务闭环。它通常负责任务状态、上下文拼装、工具注册与权限、循环/预算/超时、重试与幂等、人工审批、日志 trace、结果验收和恢复。模型负责不确定的语义判断，Harness 用代码约束确定性的生命周期；因此它不是 Prompt，也不等于某个具体框架。

### 6. 长程任务平时 5 分钟能结束，第二次却运行 15~20 分钟，如何分析延迟？

**参考回答：**

先用同一 `task_id` 的 trace 对比两次运行，把总耗时拆成模型 TTFT/生成、工具排队和执行、网络、重试、人工等待、上下文处理等阶段。重点检查：输入 token 是否膨胀、是否发生重复检索/工具调用、模型是否陷入循环、下游 P95 是否变慢、限流或连接池是否排队、缓存是否失效，以及是否因为错误重试放大。

按时间线和 span 找到最大差异，再用指标和日志复现；不能只看平均耗时。给每一步记录 `start/end、attempt、token、tool_name、status、error_code`，设置预算和超时后再定位根因。

### 7. 如何解决上述长任务延迟问题？

**参考回答：**

先止损：设置全局 deadline、最大步数和单工具超时；对可重试错误使用指数退避和上限，对不可重试错误立即失败或降级。再优化热点：裁剪/摘要历史上下文、缓存稳定检索和工具结果、并行执行无依赖步骤、使用流式输出、连接池和批量 Embedding。对重复动作做循环检测，对长任务使用 checkpoint，支持断点续跑。

最后用分桶回归验证：正常、长上下文、工具失败、下游变慢各自比较 P50/P95、完成率、重试率和成本，灰度后保留回滚开关。

### 8. 工具有固定入参，需要模型结合上下文提供，如何保障调用可靠性？

**参考回答：**

工具声明采用严格 JSON Schema，参数由模型提出，但在 Tool Gateway 再做类型、枚举、范围、租户和权限校验。对关键参数让模型先引用上下文证据或向用户确认；缺字段返回结构化 `NEED_INPUT`，不要让模型猜。执行层设置超时、限流、熔断、幂等键和审计日志；网络抖动等瞬时错误可有限重试，写操作必须可幂等。

工具结果也要有统一 envelope（状态、数据、错误码、来源、版本），限制大小并脱敏。最终由验收器检查实际副作用，不能以模型说“调用成功”作为完成依据。

### 9. 随着提问轮次增加，上下文窗口越来越大，如何解决？

**参考回答：**

把上下文分层：系统规则和当前目标最高优先级；当前任务状态、待办和最近工具结果保留；旧对话做带时间和来源的摘要；可重新获取的事实只保留引用 ID，按需 RAG 召回。设置 token 预算和淘汰优先级，定期压缩，并保留原始消息在外部存储以便审计和回放。

压缩前后做关键信息回归（实体、约束、未完成项、证据 ID），避免摘要把事实写错。不同任务使用不同会话状态，防止无关历史串入当前请求。

### 10. 压缩/摘要必然丢信息，如何使信息损失最小化？

**参考回答：**

先定义不可丢字段：用户目标、硬约束、数字、时间、实体、工具结果、错误、待办和证据来源；用结构化状态保存它们，摘要只处理自然语言叙述。采用分层摘要（轮次摘要、阶段摘要、任务摘要），每次摘要保留原文消息范围和版本。

压缩后用规则和独立校验模型检查数字/实体/否定词是否一致，并在必要时回读原文；高风险任务宁可减少上下文或请求用户确认。通过包含长对话、冲突约束和数字的评测集比较召回率、任务完成率和事实一致性。

## 三、算法题

### 11. 给定一个数 n 和数字集合 A，求由 A 中元素组成且小于 n 的最大数

例如 `n=23121，A={2,4,9}`，答案为 `22999`。

**参考解法：**

优先构造与 `n` 等长的最大数。按位从左到右尝试不超过当前上界的数字；若当前位置只能选更小数字，后缀全部填集合中的最大数字；若只能选相同数字则继续比较下一位。某一位无法继续时回退到前一位，换成严格更小的数字，再把后缀填成最大值。若等长无解，答案是少一位且全部由最大数字组成的数；若集合含 `0`，要避免多位数首位为 0。

```python
def max_less_than(n: int, digits: list[int]) -> int | None:
    ds = sorted(set(digits))
    if not ds or any(d < 0 or d > 9 for d in ds):
        raise ValueError("digits must be distinct decimal digits")

    s = str(n)
    memo = {}

    def dfs(i: int, tight: bool, started: bool):
        key = (i, tight, started)
        if key in memo:
            return memo[key]
        if i == len(s):
            # 到达等长末尾时 tight=True 表示刚好等于 n，不满足“小于”
            return None if tight else ""
        upper = int(s[i]) if tight else 9
        best = None
        for d in reversed(ds):
            if d > upper or (not started and i == 0 and len(s) > 1 and d == 0):
                continue
            nxt = dfs(i + 1, tight and d == upper, started or d != 0)
            if nxt is not None:
                cand = str(d) + nxt
                best = cand if best is None or cand > best else best
        memo[key] = best
        return best

    ans = dfs(0, True, False)
    if ans is not None and ans and int(ans) < n:
        return int(ans)

    # 等长无解时取短一位最大数；没有非零数字则无解
    non_zero = [d for d in ds if d != 0]
    if len(s) == 1:
        return max((d for d in ds if d < n), default=None)
    if not non_zero:
        return 0 if 0 < n else None
    return int(str(max(non_zero)) + str(max(ds)) * (len(s) - 2))
```

上面递归的关键是 `tight`（是否仍受 n 的前缀约束）和记忆化；生产代码还应补充空集合、`n<=0`、只含 0 等边界测试。对示例得到 `22999`。
